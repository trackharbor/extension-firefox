# Firefox: копирование заголовков Spotify

## Цель

По нажатию на иконку расширения получить заголовки текущего аккаунта Spotify
и скопировать их для ручной вставки в окно авторизации TrackHarbor.
Сервер и другие существующие вкладки не изменять.

## Согласованное поведение

1. Создать отдельную активную вкладку `https://open.spotify.com/`.
2. Наблюдать только её запросы к
   `https://api-partner.spotify.com/pathfinder/v2/query` (query string допустим).
3. Из одного запроса прочитать оба заголовка, без учёта регистра имён.
   Пропускать запросы без обоих непустых заголовков; не объединять разные запросы.
4. Проверить, что authorization содержит `Bearer ` и непустой токен.
5. Скопировать в буфер ровно две строки:

   ```text
   authorization: Bearer <фактический токен>
   client-token: <фактический client-token>
   ```

6. Открыть небольшое окно расширения с сообщением «всё ок» и пояснением,
   что заголовки скопированы. Затем закрыть только созданную вкладку Spotify.
7. При ошибке открытия/загрузки страницы, перехвата, копирования или
   тайм-ауте 60 секунд показать в том же окне понятную ошибку и закрыть
   созданную вкладку. При ручном закрытии вкладки сообщить о прерывании.
   Ошибку закрытия отобразить, не заявляя об успешном закрытии.

Успех означает получение и копирование заголовков, а не проверку их сервером.
Пользователь должен быть авторизован в Spotify; автоматического ввода пароля нет.
Если вход нужен, его можно выполнить в открытой вкладке в пределах тайм-аута
или войти заранее и повторить запуск.

## Варианты реализации

- **Выбран:** Firefox WebExtension с постоянной фоновой страницей Manifest V2,
  `webRequest.onBeforeSendHeaders`, записью в буфер и отдельным окном результата.
  Не зависит от DOM Spotify, не требует сервера и позволяет завершить очистку
  при переключении вкладок.
- Content script с перехватом fetch: менее надёжен, требует внедрения в контекст
  страницы, может пропускать другие способы отправки запросов; не используется.
- Отправка заголовков прямо в TrackHarbor: требует адреса сервера, авторизации
  и нового интерфейса; выходит за согласованный объём.

## Компоненты

- `manifest.json`: иконка действия, фоновая страница, разрешения `webRequest`,
  `clipboardWrite` и доступ только к `open.spotify.com` и `api-partner.spotify.com`.
  Не запрашивать cookies, clipboardRead или доступ ко всем сайтам.
- Фоновый контроллер: одна операция за раз, обработчики запросов и ошибок,
  таймер, копирование, показ результата и очистка. Сначала создать пустую
  вкладку и запомнить ID, затем перейти на Spotify, чтобы не пропустить запросы.
  Повторное нажатие во время операции не создаёт дополнительные вкладки.
- Чистая функция разбора/форматирования заголовков для отдельных тестов.
- Страница результата: только безопасный текст, без токенов, с кнопкой закрытия.
  Если открыть окно невозможно, использовать сообщение через значок действия;
  невозможность показать окно не должна мешать закрытию вкладки Spotify.

## Безопасность

Токены существуют только в памяти на время копирования и в буфере пользователя.
Не писать их в логи, storage, URL окна результата или файлы. Не отправлять
на TrackHarbor или другие серверы. Состояние результата содержит только статус
и безопасное сообщение. Не показывать необработанные исключения, которые могут
содержать URL или секреты. Запросы Spotify не блокировать и не изменять.

## Проверка и поставка

Автотесты: формат, регистр имён, отсутствие/пустота заголовков, неверный Bearer,
посторонние вкладки и URL, повторные события, тайм-аут, ручное закрытие,
ошибки открытия/копирования/показа результата/закрытия, очистка таймеров.
Тесты контроллера используют заглушки Firefox API, не реальный аккаунт.

README на русском: сборка ZIP/XPI, временная установка через
`about:debugging#/runtime/this-firefox`, запуск и вставка в TrackHarbor,
предупреждение о чувствительности буфера. Для постоянной установки в обычный
Firefox требуется подпись Mozilla; локальная упаковка сама по себе её не даёт.
Живая проверка с аккаунтом Spotify остаётся отдельной ручной проверкой.
